## 0.5.20 — 2026-10-08

### Small rectangle covers are no longer dropped

- A rectangle cover used to be thrown away, with no message, if it came out under 1% of the image in width or height. That limit was measured against the image, not the screen. On large or tall images 1% can be 20 or more pixels on screen, so a cover for a single line of label text vanished on the second click. On a tall diagram shown 2337px high, for example, any cover shorter than about 23px was dropped.
- Rectangles are now kept if they are at least 3 pixels on screen in each direction (`MIN_SHAPE_PX` in `src/types.ts`, checked in `commitRectDraft`). A second click on the same spot as the first still cancels the rectangle, as before.
- The resize handle uses the same 3-pixel minimum, so an existing cover can be shrunk down to label size. Before, it stopped at 1% of the image.
- Polygons never had the 1% check, so the Polygon tool could already draw small covers. Their bounding box no longer gets padded out to 1% of the image either. The old 0.01 floor in `commitPolyDraft`, `normalizePolygon` and `normalizeTargetRegion` is now a tiny divide-by-zero guard (`MIN_SHAPE_FRAC`).
- Existing covers and saved files are unchanged. No migration runs.

- Version 0.5.20 in `manifest.json`, `package.json` and `package-lock.json`, a `versions.json` entry (minAppVersion 1.7.2), and a CHANGELOG entry.
